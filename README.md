# StudyFlow

Календарь самостоятельного обучения: общий учебный план и личный прогресс каждого участника. Главная страница доступна без входа и показывает месяц. Можно переключиться на неделю, читать темы и открывать материалы. Авторизация требуется при отметке выполнения, открытии личных разделов и создании календаря.

## Запуск

Node.js 22.12+ (рекомендуется Node 24), npm 10+. Для better-sqlite3 при отсутствии готового бинарника нужны Python и инструменты сборки C++.

```bash
npm install
npm run db:migrate
npm run dev
```

По умолчанию frontend: http://localhost:5173, backend: http://127.0.0.1:3007. Если порт занят, скопируйте `.env.example` в корневой `.env` и задайте, например, `APP_ORIGIN=http://127.0.0.1:5174`. Vite берёт порт из APP_ORIGIN и проксирует `/api` на PORT backend. strictPort исключает незаметную смену порта.

```bash
npm run typecheck
npm run test
npm run build
```

В production после сборки задайте `NODE_ENV=production`, `SESSION_SECRET` (минимум 32 случайных символа), `APP_ORIGIN=https://your-domain.example` и выполните `npm start`. Express обслуживает frontend и API; HTTPS завершается на reverse proxy к `127.0.0.1:3007`. Доверяется один reverse proxy. Production-cookie имеет Secure, HttpOnly и SameSite=Lax.

| Переменная     | По умолчанию                                  |
| -------------- | --------------------------------------------- |
| PORT           | 3007                                          |
| DATABASE_PATH  | ./data/studyflow.sqlite, относительно `back/` |
| SESSION_SECRET | Ключ только для локальной разработки          |
| APP_ORIGIN     | http://localhost:5173                         |
| NODE_ENV       | development                                   |

Все данные и сессии физически хранятся в SQLite и переживают перезапуск. Foreign keys, WAL и busy_timeout включены. Миграции версионируются в `migrations`; запускаются также при старте backend. Для резервного копирования используйте SQLite backup API, а не копирование только основного файла при работающем WAL.

Инструкция для VPS и домена `go.its-403.ru`: [docs/deployment.md](docs/deployment.md). Готовые конфигурации находятся в `deploy/`.

## Два пространства

- **Просмотр** — `/` или `/?calendar=<id>`. Месяц по умолчанию, неделя по переключателю. Карточка открывает описание, материалы и историю. Checkbox меняет только личный прогресс. Если пользователь не вошёл, появляется модальная форма входа; после успешного входа выбранное действие продолжается. Форму можно закрыть и продолжить просмотр.
- **Мастерская** — `/studio?calendar=<id>`. Создатель меняет темы, даты, описания и источники. Checkbox выполнения здесь отсутствует. Ссылка «Открыть просмотр» ведёт в учебное пространство. Новые календари создаются приватными. В настройках автор может явно включить открытый доступ или снова закрыть его.
- **Мой прогресс** — `/progress`, только после входа. Личные достижения по собственным и открытым изучаемым календарям.
- **Профиль** — `/profile`, имя и IANA timezone.

В месячной сетке на десктопе видны две компактные темы. Для остальных есть заметная кнопка «Ещё N тем», открывающая полный список дня с названиями, отметками и доступными автору действиями. Внутри плиток нет скрытой прокрутки; дату дня также можно нажать для открытия списка.

Навигация, профиль, смена оформления и вход расположены в компактном header. На мобильном месячная сетка показывает даты и точки активности, а выбранный день — список тем под сеткой. Редактор темы и авторизация открываются по центру с ограничением фокуса, Escape и восстановлением фокуса при закрытии.

## Роли и приватность

Роль **creator** определяется сервером по `calendars.ownerId`. Она относится к конкретному календарю: любой пользователь может создать собственный план, но не получает права редактировать чужие. Автор меняет общий план; участник может завершать и возвращать в план только собственные темы прогресса.

Открытый календарь виден без входа и присутствует в списке открытых планов. Приватный видит только его создатель. Проверки применяются к метаданным, добавлению и изменению тем, ресурсам и API пространства редактирования. Чужие приватные ID возвращают 404. Подмена `calendarId` не позволяет перенести тему в чужой календарь.

Миграции `0002_calendars` и `0003_personal_schedule` переносят прежние данные каждого пользователя в **приватный** календарь и сохраняет даты, заметки, источники, историю и отметки выполнения. Существующие пользовательские данные не становятся открытыми автоматически.

Для гостевой главной страницы один раз создаётся отдельный открытый календарь Go/Backend с 45 занятиями по будням и 107 ссылками на материалы. Его технический автор StudyFlow не имеет доступного пароля. План рассчитан на 9 ноября 2026 — 8 января 2027, около 3 часов в день (135 часов). Выходные свободны, новогодние будни включены. Исходное содержание находится в `docs/go-backend-plan.md`; обновление общего плана выполняется один раз и заменяет его прежние темы вместе с их прогрессом и заметками. Пользователи создают собственные календари; в пустой календарь можно добавить готовый четырёхнедельный план с выбранной датой старта.

**Описания и заметки темы являются частью общего плана.** При открытии доступа они видны всем вместе с источниками. Личные отметки, времена завершения, переносы и достижения не публикуются. Отдельные личные конспекты участников в этой версии не добавлены.

## Общие даты и личные переносы

`topics.planDate` — дата в общем расписании автора. В редакторе и для гостя показывается именно она. `originalDate` сохраняет первоначальную дату.

У каждого вошедшего участника есть отдельная запись `topic_progress`: пользователь, тема, личная дата выполнения, completedAt и история переносов. Она создаётся при открытии выбранного календаря после входа. В SQLite-транзакции незавершённые темы с личной датой раньше сегодняшней переносятся сразу на текущий локальный день. Один интервал истории представляет все пропущенные дни; копий тем не возникает. Повторная синхронизация в тот же день ничего не меняет. Завершённые темы автоматически не переносятся.

Синхронизация использует серверное время и IANA timezone пользователя. Вызывается перед загрузкой календаря, при возврате на вкладку и при смене локального дня (проверка каждые 15 секунд). GET диапазона также обеспечивает актуальность. При закрытом браузере изменения обрабатываются при следующем обращении. Просмотр редактора не запускает личные переносы.

Перенос участника не меняет общую дату и не влияет на других. Ручная смена даты автором сохраняется в общей истории и обновляет личную назначенную дату участников; фактическое время завершения сохраняется. Старые дни показывают информационные записи о переносе в недельном виде и в истории темы, без дублирования самостоятельных задач.

Для совместимости старые `/api/calendar/*` и `/api/topics/:id/complete|reopen` сохраняют поведение прежнего личного календаря автора. Новый интерфейс использует API `/api/calendars/*` и изолированные записи прогресса. Старый sync не меняет `planDate`.

## Статистика

Расчёты выполняются сервером, completedAt хранится в UTC и переводится в текущий timezone пользователя. Смена timezone может изменить распределение достижений по дням.

- Завершено за период: темы, фактически завершённые внутри выбранного месяца или недели.
- Знаменатель прогресса: уникальное объединение тем, назначенных на период в личном календаре, и завершённых в период. Процент не превышает 100%; пустой план даёт 0%.
- Дни соседних месяцев показаны в сетке, но исключены из месячной статистики.
- Серия: последовательные локальные дни с завершениями, начиная сегодня либо вчера. Если оба дня пропущены, серия равна 0.
- Всего изучено: темы, имеющие сейчас личный статус completed. Возврат в план явно очищает completedAt; повторное завершение уже завершённой темы не меняет его.
- Страница прогресса агрегирует свои темы и личный прогресс по доступным открытым календарям. Закрытый чужой календарь исключается из агрегата, но его записи прогресса сохраняются на случай повторного открытия.

Гостю всегда показываются нулевые личные достижения, а не прогресс автора.

## API

Все изменяющие запросы требуют session cookie, допустимого Origin и X-CSRF-Token (включая вход/регистрацию). Токен выдаётся `GET /api/auth/csrf`, обновляется после регенерации сессии при входе. Ошибки: `{ "error": { "message": "…", "code": 400 } }`. Авторизация ограничена 30 попытками с IP за 15 минут. Используются Helmet, Zod, bcrypt; password hash не возвращается.

| Метод            | Endpoint                                              | Доступ / назначение                                                    |
| ---------------- | ----------------------------------------------------- | ---------------------------------------------------------------------- |
| GET              | /api/calendars                                        | Открытые календари + собственные приватные                             |
| POST             | /api/calendars                                        | Вход; `{title,isPublic?}`, по умолчанию приватный                      |
| PATCH            | /api/calendars/:id                                    | Только создатель; title, isPublic                                      |
| GET              | /api/calendars/:id/range?start=…&end=…                | Открытый просмотр или собственный календарь, максимум 42 дня           |
| GET              | /api/calendars/:id/range?…&mode=edit                  | Только создатель, общие даты, без личных отметок                       |
| POST             | /api/calendars/:id/sync                               | Вход; синхронизация личного календаря                                  |
| GET              | /api/calendars/:id/topics/:topicId                    | Доступная тема; mode=edit только создателю                             |
| PATCH            | /api/calendars/:id/topics/:topicId/complete           | Вход; отметить только для себя                                         |
| PATCH            | /api/calendars/:id/topics/:topicId/reopen             | Вход; вернуть только свой прогресс                                     |
| POST             | /api/calendars/:id/plan                               | Только создатель, только пустой календарь; `{start}`                   |
| POST             | /api/topics                                           | Только создатель; title, scheduledDate, calendarId, notes?, resources? |
| GET/PATCH/DELETE | /api/topics/:id                                       | Только создатель; управление общим содержимым                          |
| POST             | /api/topics/:id/resources                             | Только создатель; title, HTTP/HTTPS url                                |
| PATCH/DELETE     | /api/topics/:id/resources/:resourceId                 | Только создатель                                                       |
| POST             | /api/auth/register, /api/auth/login, /api/auth/logout | Регистрация, вход, выход                                               |
| GET              | /api/auth/me                                          | Текущий пользователь                                                   |
| PATCH            | /api/users/me                                         | Имя, timezone                                                          |
| GET              | /api/stats/overview                                   | Личная статистика текущей недели                                       |
| GET              | /api/stats/weekly?start=…                             | Личная статистика выбранной недели                                     |

Для месячного диапазона необязательные periodStart/periodEnd ограничивают период статистики внутри запрошенной сетки. Даты — YYYY-MM-DD. PATCH темы без notes или resources сохраняет существующие значения; переданный resources атомарно заменяет список. Лимиты: 200 символов названия темы, 100000 заметки, 30 источников, пароль 8+ символов и максимум 72 UTF-8 байта.

## Структура и технологии

- `front/`: Vue 3, TypeScript, Vite, Vue Router, Pinia, Tailwind CSS, Lucide, Luxon, marked + DOMPurify.
- `front/src/components/`: MonthlyCalendar, WeeklyCalendar, TopicCard, TopicReader, редактор темы и диалоги.
- `front/src/composables/`: состояние календаря, диапазоны и общая клавиатурная доступность диалогов.
- `back/`: Express, TypeScript, Drizzle ORM, better-sqlite3, express-session с SQLite store.
- `back/src/modules/calendars.ts`: открытый просмотр, права создателя, личный прогресс и переносы.
- `back/src/modules/calendar.ts`: прежний транзакционный сервис личных переносов автора.
- `back/src/modules/statistics.ts`: серверные формулы статистики.
- `back/src/db/`: схемы и версионируемые SQL-миграции.
- `back/test/`: критические бизнес-правила, интеграционные HTTP-сценарии и миграция существующих данных.

Не реализованы восстановление пароля, email, совместное редактирование и социальные функции. Создатель у календаря один. Код и схема поддерживают несколько независимых календарей одного пользователя.

## Проверка текущей версии

- `npm run db:migrate`: миграции до `0003_personal_schedule` применены; локальная резервная копия перед обновлением сохранена в игнорируемом `back/data/before-calendars.sqlite`.
- `npm run typecheck`: frontend и backend проходят.
- `npm run test`: 32 теста в трёх файлах проходят, включая HTTP API, миграцию старой базы, независимый прогресс, смену сессии/CSRF и продолжение выбранной отметки после входа.
- `npm run build`: production frontend и backend собираются.
- В браузере проверены гостевой месяц, запрос входа по галочке, вход и выполнение, переключение недели, мастерская создателя, форма темы и мобильная сетка с выбранным днём на 400 px.

Личные заметки доступны в подробностях темы в режиме просмотра. Они сохраняются отдельно от общего описания и видны только вошедшему пользователю. Текст сохраняется кнопкой «Сохранить заметку»; для удаления содержимого очистите поле и сохраните. При закрытии темы с несохранёнными изменениями появится предупреждение. Миграция `0004_personal_notes` применяется автоматически при запуске сервера.
